Ravenroot now records, for every accepted execution, the dependency set that execution was actually resolved against — the exact document it was accepted with, the submission policy and unknown-behavior stance it runs under, the graph and traversal limits in force, the engine and store it was admitted on, the program runtime composed with it, and each installed node package by id, version and SDK contract. The record is written before the acceptance that references it, so an accepted execution always has one; it is immutable and scoped to a single tenant; and it holds only references, versions and digests, never a credential or an authorization snapshot. Before an execution is first dispatched and before it is recovered, resumed, restarted after a hold or taken over by another worker, that record is read back, checked against the digest stored beside it, and compared with what the running deployment resolves now. Anything that differs — a changed limit, a changed policy, a node package at a different version, a missing or damaged record — refuses the work with a diagnostic naming what differs, rather than quietly running the same graph with different behavior. Refused recovery work is left claimable rather than discarded, and retention will not remove a record while its execution still exists. `GET /v1/executions/{id}/manifest` reports one execution's record identity and whether this deployment still matches it, without disclosing the deployment's own configuration. Three limits are stated rather than implied: a node package is identified by version and not by a content digest, so a package republished under an unchanged version is not detected; a program artifact's approval state is deliberately re-checked at execution rather than pinned, so revocation keeps working; and executions accepted before a deployment turns this on have no such record and are refused by the paths that verify rather than being reconstructed from today's environment.
