Ravenroot now classifies the durable work it inherited before it accepts traffic, and recovers an author's repeatability decision from the retained graph document rather than losing it with the process that accepted the execution. On startup a deployment lists its interrupted process instances and, for each, reads back the exact document and execution manifest that instance was accepted against; `GET /ready` answers `503` with the new `RECOVERING` state until that pass completes. A pass that cannot read the store does not complete, so readiness stays closed and it retries; a pass that completes having refused some instances does open readiness, because inherited work this deployment cannot rebuild is an operator fact rather than a reason to stop serving unrelated tenants, and each refusal is reported individually so one damaged instance never hides the rest. Every recovered item now passes through one recovery coordinator with explicitly registered adapters, exactly one of which may own an item, and the coordinator refuses an execution whose document or manifest does not resolve here before any adapter is asked. How long such work is withheld depends on whether waiting could change the answer: durable state that could not be read is waited on indefinitely and consumes no delivery budget, while a document or manifest that is absent, unverifiable or describes another deployment is withheld for a bounded number of deliveries — a window to correct the deployment — after which an attempt that was already in flight is parked with a cause naming the fault, because it stands for an effect whose outcome nobody knows and withholding that forever is worse than putting the decision in front of an operator. An attempt that had not started is never parked, since it produced no effect to adjudicate. Due timers are outside this gate entirely: closing a durable wait commits store transitions and rebuilds nothing, so tasks still expire and approvals still lapse on an execution this deployment cannot rebuild, while the re-entry an expiry produces is gated like anything else. Recovery is composed wherever a durable store is configured rather than only where durable tool approvals or human tasks are enabled, and transient and deployment-hosted work are classified by the same authority while each keeps its own deployment and workload relationship. Because the retained document is now read back during recovery, an effect whose outcome a crash left unknown is redelivered under its original effect identity when the node declares `recovery.repeatable`, where every such effect previously parked for want of a graph to consult; a node declaring the opposite, or declaring nothing, still parks for a human decision, and a value on a node whose type never declared the property remains inert. One limit bounds what resumes automatically: the durable record holds lifecycle state and not the data passing between nodes, so an interrupted node attempt has no recorded input and is discovered, classified and reported rather than re-executed from an invented one. Work whose committed boundary recorded enough to continue from — a settled handler, a due timer, a tool-approval or human-task continuation, an operator-resumed hold — is unaffected and resumes as before.
