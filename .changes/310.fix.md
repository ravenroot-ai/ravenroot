A pull request into `dev` had regressed to publishing the required `ci-required` check from a small
`admission` diagnostic tier, without the full test suite ever running on the pull request's head. This
repository first tried closing that gap by removing the `pull_request` trigger for `dev` entirely and
verifying the review candidate with a full run dispatched on its exact commit instead. That change was
tested against real pull requests and reverted: GitHub's required-checks evaluation for a pull request
only sees check suites from that pull request's own events, never a `workflow_dispatch` suite living
on the same commit, so a pull request into `dev` was left with `ci-required` absent rather than green,
and could never be queued or merged.

`pull_request` into `dev` is restored and now earns the full tier directly from the classifier, not
the retired `admission` diagnostic — a fork's pull request the same way as a repository branch's,
without any manual step. The dispatched review-candidate run and the routed Dependabot dispatch
continue to exist for verifying a commit before its pull request opens or before a Dependabot update
can reach `dev`. The `admission` tier's retired jobs remain in the fast feedback workflow for every
work-branch push, so contributors still see that signal on every push. The net capacity cost is one
additional full run per change: once on the pull request's own event, once more when the merge queue
verifies the integration commit.
