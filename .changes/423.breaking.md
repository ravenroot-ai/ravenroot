Explicit Workspace lifecycle nodes and named Agents replace the generic workspace-agent node.
Workspace scope and container reuse are independent, with durable cancellation, pool scheduling,
operator-sized capacities and supervised workers. A separate PostgreSQL-backed runner coordinator
can scale independently of workers; the full graph/authoring server remains single replica.
Upgrade requires stopping writers, taking a verified backup, starting the upgrade so it applies the
complete SQLite schema transition through migration 32 or PostgreSQL transition through migration 12,
and replacing old generic graph nodes with a Workspace plus Agents using typed workspaceRef. Before
restoring traffic, check readiness, list a known pre-upgrade task, exercise a dry-run reconciliation,
and test capability revocation across a replica restart. Ordinary Agent graphs are unchanged. Writable
model-backed execution requires an approved model profile, Landlock-capable Linux and positively
verified storage quotas; unsupported hosts fail closed. Trusted-local `service.sh start --runner` and
restart supervise a tokenless in-process worker; public loopback users and the private workload
channel remain structurally separate. Stop includes retained Workspaces. CI now requires secretless
native model-protocol, Landlock/seccomp and XFS evidence; live-provider smoke is a separate owner-only
local opt-in and never a merge prerequisite.
