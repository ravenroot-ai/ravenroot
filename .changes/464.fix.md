Deployment lifecycle clients now use the server's durable command contract. HTTP, CLI, and the
Deployments window expose authoritative generations, send unique idempotency keys and required
operator metadata, parse every typed command outcome, and reconcile state without replaying refused
decisions. Legacy process-local and source-session deployments remain compatible, while durable
Undeploy retains tombstone replay and removes its local runtime. Durable local IDs now keep a
non-expiring tenant-scoped identity binding across complete restarts and command-ledger purge, and a
second lost command response triggers authoritative read reconciliation without a third delivery or
an invented outcome. Undeploy confirmation text now distinguishes permanent durable tombstones from
reusable process-local registrations.
