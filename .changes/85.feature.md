A graph node can now declare a bounded orchestration retry policy, and each retry is recorded as a
distinct durable attempt with an increasing ordinal instead of the attempt history stopping at one. A
node declares `retry.maxAttempts` together with `retry.retryOn`, the list of failure types it considers
safe to retry, and optionally `retry.initialBackoff`, `retry.backoffMultiplier` and `retry.maxBackoff`;
a node that declares nothing retries nothing, exactly as before. Only failures classified as retryable
are repeated — a failure whose outcome is uncertain is never repeated automatically — and cancellation,
graph shutdown and a used-up attempt budget all stop further attempts promptly, including while a
backoff is still being waited out. A retry decision is committed before its backoff begins, so a
restart resumes it rather than losing it and cannot turn one retry into two attempts. Events and
metrics now carry the attempt ordinal and report retries a connector performed internally separately
from retries the orchestrator made, so an initial attempt, a retry and a connector's own retries can be
told apart; a retried attempt publishes the new `NODE_RETRY_SCHEDULED` event in place of `NODE_FAILED`,
which continues to mean that a node's visit failed.
