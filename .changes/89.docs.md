The per-domain close bound behind the deployment-admission contract's shutdown budget is now measured
and cited: 20 seconds, from each supported execution engine's own two-phase (stop, then cancel-on-timeout)
close bound, giving a fixed worst-case pod shutdown time of 66 seconds that does not grow with the number
of active deployments. That independence — domains closing concurrently rather than one after another —
is now proven by a deterministic, synchronization-based conformance test in place of the previous check,
which passed without ever being able to detect a serialized close. The default active-deployment cap
(`RAVENROOT_MAX_ACTIVE_DEPLOYMENTS`, still 8) is unchanged in value; its justification is now stated
explicitly as a per-pod resource ceiling decoupled from the shutdown-time formula, rather than a
placeholder pending that formula's missing term.
