# Ravenroot 0.9.0-alpha.1

Ravenroot 0.9.0-alpha.1 delivers the work integrated since `0.8.0-alpha.1`. It contains breaking
changes: read *Breaking changes* below before upgrading, together with the compatibility policy and
the operator guides. Pin every Maven and OCI dependency to this exact version, and use an immutable
container digest where deployment reproducibility matters.

## Breaking changes

- Managed graph links retain repository identity and revision, and the editor offers a searchable, paginated source picker. Release makes the authored version immutable independently of publication. Saving changed content from released vN atomically creates draft vN+1; opening or saving unchanged content does not advance the version. The provider-neutral versions API and confirmed editor action also allow explicit successor creation before editing. Subsequent saves, content restores and explicit discard retain its assigned successor version. Back up legacy divergent vN work before explicitly reconciling and reapplying it to a successor. Publication and deployment remain separate. Reopening an already-open managed source preserves unsaved work and refreshes clean sources in place; workspace restoration protects unsaved managed changes and repository scope.
- Deploy now activates SOURCE listeners without running START; first Run binds the originating document
  to its pinned deployment and admits at most one initial START, including across restart and lost
  responses. Closing a bound document offers explicit Stop or observation-only detach; Stop is fenced
  to the originating runtime or immutable durable registration and pinned graph. Source events enter their owning node, while incoming edges stop at SOURCE boundaries.
  Durable scoped business histories, explicit selectors and context derivation/closure, outgoing
  business headers, cross-traversal contribution joins, bounded SDK/API/CLI history search and shared
  editor/embed traversal inspectors support independent callbacks without conflating transport IDs.
  Upgrade SQLite to schema 41 or PostgreSQL to schema 21 and follow the correlation migration/backup
  guide; old records retain explicit unavailable states. These contracts target 0.9.0-alpha.1 through
  the normal release preparation, authorization and publication procedure.

  Identity-sensitive document Start and Stop capture the server-issued runtime incarnation before activation. Queued Stop survives document closure, suppresses a pending initial START, and never redirects to a replacement registration. Authenticated status exposes the optional bounded `runtimeIncarnationId`; secured SDK overloads fail closed when identity fencing is unavailable.
- Kubernetes pools now require Kubernetes 1.34 or newer, `PodLevelResources` enabled consistently on the API server, scheduler and every kubelet, a 100 ms CFS quota period, and approved CPU ceilings of at least 20m. Enable these prerequisites before starting managers. The approved Pod CPU request and limit and all memory budgets remain unchanged; the Agent container's CPU request and limit are now 80% of the approved ceiling, rounded down to an integer millicore. Preflight rejects missing or changed resource budgets and requires fresh positive own-container CPU-throttling evidence within ten seconds; ancestor counters and elapsed time cannot substitute for that proof.

## Security

- Constrain the real-browser observation replay fixture to its owned backend and pass complete CI verification data through bounded files so large promotions reach the required gate.

- Update the UI and configurator development tooling to Vite 7.3.7 to include the launch-editor security fixes and keep their complete dependency audits passing.

## Fixes

- Execution-result reads retain their actual output and node evidence when durable completion races result publication, without reporting successful completion from an earlier running projection.

- Reduce repeated Git graph-authoring reads with a persistent, paginated SQLite or PostgreSQL summary index, bounded verified content reuse, and incremental reconciliation for GitHub and GitLab. Repository authorization, publication verification and expected-revision mutation checks stay active on cache hits. Opaque list continuation cursors preserve a complete synchronization generation; expired cursors restart from the first page. Existing numeric cursors remain accepted.

  Connect opt-in authenticated GitHub/GitLab webhook delivery to bounded reconciliation and periodic recovery in packaged and embedded servers. Reuse GitLab file metadata through HEAD without retransferring cached GraphML, preserving remote mutation checks and counting content-bearing fixture responses accurately.
- Make saga authoring optional and explicit. Ordinary node creation, editing, reusable-node insertion
  and GraphML round trips no longer inject saga defaults. Add graph scope management and individual
  trusted-participant controls; diagnostic Log remains outside sagas. Repair only the confirmed
  historical default-Log signature and retain incomplete or intentional declarations for authoritative
  validation. Report safe node/property saga admission findings while preserving durable saga,
  compensation, recovery and outbox guarantees.
- Preserve deployment monitoring and history across reload, separate drawing from durable execution admission, expose authorized submitted source, and create the next repository draft atomically when a released version changes. Confirm live deployment observation before the first traversal, preserve replay from its scoped lifecycle cursor, and retain the original request for bounded observation retries even when the drawing is unavailable. Clear captured node and edge runtime paint when observation ends, including Stop, undeploy, gaps and revoked access, without repainting a replacement document.

  Publish successful GraalVM program outcomes after coordinated session cleanup and admission closure,
  and settle failures only after the same cleanup and close attempts.
  Cancellation and revocation share the existing bounded cleanup attempt, including late launch results;
  cleanup or close failures remain explicit without claiming that failed cleanup proves process-tree reaping.
- Integrate optional isolated GitHub graph release proposals, validate current review identities and refs,
  and expose authorized durable named SOURCE triggers with restart-stable actor-bound deduplication.
  Preserve the existing authoring dialog while reporting uncertain acknowledgement, bounded exact-candidate
  release/publication observation, and same-identity retries across browser reloads.
- Keep AMQP listeners ready and listening when individual deliveries are rejected for missing stable identity, invalid metadata or oversized content. Report these rejections separately from listener health, and restore healthy status after durable acceptance and broker acknowledgement. Actual broker and durable-ingress failures continue to report degraded health.
- Deployment History now keeps business histories beside a large pinned graph, with a compact traversal chooser, readable state badges, and node visits and attempts below the graph. Graph & timeline shows the selected traversal; Traversal map compares two bounded previews. Full identities remain inspectable, incomplete coverage stays explicit, and the native toolbar preserves access to actionable Human Tasks. Monitoring continues to open the live elastic graph.
- Restore live node and edge activity in the originating graph and read-only deployment views, including durable deployment identities. Monitoring again opens the elastic graph; a separate History command opens pinned traversal history. Reload checks deployment state without starting work, and hosted initial traversals no longer block Run or Test through one-shot execution reconciliation. Design now paints traversed edges without requiring an elastic renderer. Program approval respects hidden state and appears with program readiness. Missing retained deployments explain recovery through an explicit new deployment in a separate draft. Reload now reports the restored workspace accurately, and Run offers immediate recovery when its saved deployment cannot be restored.

  Recover Human Task attention using the durable registration identity on Run, reload, and explicit deployment selection. Preserve pending-task pulses in Design, show listening sources separately from the completed initial traversal, and keep graph controls below the pane title. Native deployment streams can request bounded author diagnostics so hosted log output and causal identifiers reach the activity panel.

## Other changes

- Native Kubernetes acceptance uses a conservative elapsed-time bound for quantized CPU-throttling observations while retaining the strict ten-second proof and fresh own-counter checks.

- Forward-port impact-aware verification to dev with fail-closed consumer selection, exact-candidate artifact provenance, and forced or scheduled complete regression. Preserve maintenance routing and all development browser and native acceptance coverage.
- Recognize canonical internal product-version metadata during release impact planning while retaining the licensed Akka profile exclusion and refusing substantive changes without authorized validation.
- Preserve accepted repository source bytes on an unchanged save after automatic drawing. Explicit graph or presentation edits still save normally, and edits made during a save remain unsaved until acknowledged. Switching a local graph view retains the existing replacement workflow.
